背景（根因定案——压印顺序铁证）：
  回看第 9/12/13/15 轮每次 WCUDA_DEBUG=1 的输出顺序：
    [wcuda] wcudaMalloc enter
    [wcuda] aclrtMalloc call ret=107002     ← 打印在 bridge_init 之前！
    [bridge_init] aclInit
    [bridge_init] aclrtGetDeviceCount
    [bridge_init] aclrtSetDevice(0)
  → wcudaMalloc 函数体里 aclrtMalloc 的调用点在【触发 BRIDGE_INIT 的
    WCUDA_RETURN 宏】之前，所以首个用户 API 即 cudaMalloc 时，
    aclrtMalloc 在 aclInit 前就执行 → 稳定 107002。
    前置 API（GetDeviceCount 等）成功是因为 aclrtGetDeviceCount 恰好
    会隐式完成 ACL 初始化（先 init 再进后续 malloc）。

  修复（已在源码落地，commit 83e8175 之后）：wcudaMalloc 函数体**开头**
    显式 BRIDGE_INIT()（call_once，幂等）→ 任何调用都先完成
    aclInit+GetDeviceCount+SetDevice(+CreateContext) 再走到 aclrtMalloc。
